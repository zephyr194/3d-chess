## 地形坐标

两份独立方案均选择增加横向站距，保留世界单位和既有山水、桥梁及渡船坐标。采用 `FILE_SPACING=4.4`，纵向 `SPACING=3.2`，横向站位宽度从 `25.6` 增到 `35.2`。`BASE=.545`、`GROUND=.54`、`PIECE_SCALE=.68` 和象棋规则保持原值。站位支路从 `boardPosition` 自动生成。

`board.ts` 导出 `BOARD_BOUNDS`，相机与拾取平面从它读取范围。最近站位仍使用保守的原有拾取半径，避免点击空山谷时误选远处棋位。新增宽度意味着支路会穿过新位置，必须重新验证全部实际网格支撑，不能放宽 `.44` 足迹半径或高度容差。

不采用场景根节点缩放。它会将棋子位置、道路长度、船速和支撑网格带入不同坐标度量。不逐项拉伸山峰、船体和树木，保留现有物体比例。

独立复查发现，外侧六组山脊仍按旧棋盘宽度放置，会包围拓宽后的边缘站位。保持原相机时，三个棋子中心采样方向均被挡住的数量从基线 4 枚增至 11 枚。分别试验提高相机、缩小视场角和把外山移回棋盘之外。最终让外山中心从 `BOARD_BOUNDS.halfWidth + 4.2` 派生，并把近景方向由 `29 / 21` 改为 `40 / 21`。只移动外山，不移动内场山水和渡口。实验采样遮挡数降为 2 枚，保留较低的观景角度。未采用极窄视场角，因为它超过现有轨道距离与裁剪范围。

恢复俯视按钮同时清除全景状态、恢复按钮文字并重设相机，修正原先只重复适配全景的行为。浏览器脚本现在检查相机确实回到初始近景，并保留可见性回归射线检查。

## 操作和战报

名称采用「山河弈境」。紧凑顶栏显示品牌和当前阵营，纸色战况条位于画面之外，底部操作台容纳速度、视角、音效和重置。棋盘占满可用横向空间。原有 DOM 标识和棋局面板交互保留，手机布局在画面下方换行。

一个战报组件拥有 `engage`、`capture`、`check`、`victory` 事件的文字、颜色和计时器。战斗实际开始时显示交锋，棋局提交后显示结果。每次新事件替换旧计时器，重置清除战报，避免过期回调干扰新棋局。装饰横幅不接受指针事件，不接管棋局状态。

## 动态山水

继续使用 `battlefield.update(time,reduced)` 作为单一时钟。树冠使用保存静止矩阵的实例变换，河流光纹、湖泊波纹、落叶和山间雾气做有限位移。道路、山体、站位和渡船甲板的支撑几何保持固定。减少动态效果或关闭风物动效时，恢复装饰静止姿态。

## 所有权和验证

地形代理独占 `board.ts`、`landscape-layout.ts`、`battlefield.ts` 与地形和坐标测试。界面代理独占 `index.html`、`styles.css`、`main.ts` 与战报组件。父代理拥有截图、录制、证据和文档；实现期间不交叉修改所有者文件。捕获实机证据时暂停产品源码编辑。

按 Model the Domain，坐标度量、战报事件和装饰静止姿态各有一个所有者。按 Laziness Protocol，复用支路生成和现有动画时钟。按 Prove It Works，验收使用真实走子、网格射线、原生画面与 GIF 内容。

宿主没有提供 Cursor 的 `control-ui` 和 `deslop`，因此用 Playwright 和实际差异审阅完成对应检查。所有代理依用户配置继承父模型，不声称跨模型审阅。当前 GitHub 连接器工具没有暴露，远端提交和合并使用现有 Git 连接；没有自动部署站点。
